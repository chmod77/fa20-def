# Semantic identification progress (LF6A401A / LF6A400J)

Goal (user, 2026-10-31): name and scale every table and produce a complete FA20 DIT RomRaider definition, using only evidence from the binary.

Target ROM: `roms/LF6A401A_T893ESJ92045C7207-20261024-072556.bin` (the car). Code and layouts are byte-identical to LF6A400J; only 5 table data blocks differ.

## Deliverables (current)
- `RR_LF6A401A_FA20DIT.xml` (car) and `RR_LF6A400J_FA20DIT.xml` (reference), generated by `scripts/build_named_definition.py`.
  - Identified tables are unlocked and carry name, category, output scaling and an evidence string in the description.
  - Partially identified tables keep the name of their proven role, the suffix `[output units unresolved]`, and stay locked.
  - Every other table is `Unidentified <dims> [Dxxxxxx] (<proven axes>)`, locked, in category `Unidentified - <subsystem>`.
- `scripts/validate.sh` regenerates both XMLs and checks them with RomRaider's own parser (`VerifyNamedDefinition`). The checks are: every cell and axis byte, every scaling's round trip through expression and to_byte, and that all unidentified tables are locked. Results are in `evidence/named-validation.log`.

## Toolchain (session 2)
- Ghidra 12.1.3 comes from the SourceForge mirror, because the network policy blocks GitHub release downloads. The SHA-1 is checked against the mirror listing.
- Project owner override: `JAVA_TOOL_OPTIONS=-Duser.name=shalomz`. Always run with `-readOnly`.
- `scripts/ExportAllC.java` writes `cdump/*.c`, decompiled C for all 5,633 functions. It marks the ROM read-only so literals are folded, applies per-function GBR, and labels descriptors, known variables and lookup routines. It also gives correct prototypes to the r0/r1 runtime helpers (division and variable shifts).
- `scripts/digest.py FN`: C with variable names and a table summary.
- `scripts/table_context.py FN...`: lookup call sites with the caller's arguments.
- `scripts/whowrites.py ADDR`: direct and out-parameter writers.
- `scripts/ramindex.py`, `scripts/callargs.py` (folds base+offset pointer arguments), `scripts/store_scan.py` (register-relative store resolver).
- `scripts/resolve_inputs.py`: resolves lookup inputs through parameters and call sites.
- `scripts/subsystems.py`: assigns each table to a task root.
- `scripts/ssm_join.py` and `scripts/ssm_anchor_derive.py`: map SSM addresses through the ECU table at 0x15F9D8, the formatter and the public SSM conversions.
- `scripts/semantics_db.py`: every identification and its evidence. It generates `evidence/semantics.json`.

## Key proven chains
- **Ignition.** `0x98FAC`: total timing `FFFF046C` (SSM 0x11, deg = x/2) is the sum of components in 0.5° units. The base comes from four 22x16 maps (`0x86758`), selected by `FFFF04F4.7` and `FFFF054A.4`.
- **Engine load.** `FFFF09B4` / `FFFF03A0` = VE·ρ / 1.293 g/L × 100 %. This is the speed-density model `0xCFEDC`, with R = 287 and VE = `T_02ED10`/32768.
- **Boost.** Wastegate duty `FFFF0E5E` (SSM 0x30, % = x/256) = min(initial × compensation + PI feedback, max). The target boost encoding, kPa = x/256 + 13.3, is proven from A/D channel 0x12.
- **Open-loop fuel.** OBD PID 44 formatter `0x10C32C`: λ = 256/(256 + `0B84` + `0401` + `0B42`). The fuel tables use the expression λ = 256/(256+x).
