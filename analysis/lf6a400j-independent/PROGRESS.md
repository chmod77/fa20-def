# Semantic identification progress (LF6A401A / LF6A400J)

Goal (user, 2026-10-31): name and scale every table and produce a complete FA20 DIT RomRaider definition, using only evidence from the binary.

Target ROM: `roms/LF6A401A_T893ESJ92045C7207-20261024-072556.bin` (the car). Code and layouts are byte-identical to LF6A400J; only 5 table data blocks differ.

## Deliverables (current)
- `RR_LF6A401A_FA20DIT.xml` (car) and `RR_LF6A400J_FA20DIT.xml` (reference), generated by `scripts/build_named_definition.py`.
  - Identified tables are unlocked and carry name, category, output scaling and an evidence string in the description.
  - Partially identified tables keep the name of their proven role, the suffix `[output units unresolved]`, and stay locked.
  - Every other table is `Unidentified <dims> [Dxxxxxx] (<proven axes>)`, locked, in category `Unidentified - <subsystem>`.
- `scripts/validate.sh` regenerates both XMLs and checks them with RomRaider's own parser (`VerifyNamedDefinition`). The checks are: every cell and axis byte, every scaling's round trip through expression and to_byte, and that all unidentified tables are locked. Results are in `evidence/named-validation.log`.

## Toolchain (session 2)
- Ghidra 12.1.3 comes from the SourceForge mirror, because the network policy blocks GitHub release downloads. The SHA-1 is checked against the mirror listing.
- Project owner override: `JAVA_TOOL_OPTIONS=-Duser.name=shalomz`. Always run with `-readOnly`.
- `scripts/ExportAllC.java` writes `cdump/*.c`, decompiled C for all 5,633 functions. It marks the ROM read-only so literals are folded, applies per-function GBR, and labels descriptors, known variables and lookup routines. It also gives correct prototypes to the r0/r1 runtime helpers (division and variable shifts).
- `scripts/digest.py FN`: C with variable names and a table summary.
- `scripts/table_context.py FN...`: lookup call sites with the caller's arguments.
- `scripts/whowrites.py ADDR`: direct and out-parameter writers.
- `scripts/ramindex.py`, `scripts/callargs.py` (folds base+offset pointer arguments), `scripts/store_scan.py` (register-relative store resolver).
- `scripts/resolve_inputs.py`: resolves lookup inputs through parameters and call sites.
- `scripts/subsystems.py`: assigns each table to a task root.
- `scripts/ssm_join.py` and `scripts/ssm_anchor_derive.py`: map SSM addresses through the ECU table at 0x15F9D8, the formatter and the public SSM conversions.
- `scripts/semantics_db.py`: every identification and its evidence. It generates `evidence/semantics.json`.

## Session 2 additions (later)
- Secondary tables: 121 tables read by runtime helpers in 0x16B0AC..0x16BCEC (struct and fixed-step formats) are in
  `evidence/helper-tables.json` and in the XML. The sensor scalings are identified: MAF g/s = x/76800 (0x4C53C, OBD PID10);
  IAT, IAT2, ECT, oil, battery temperature and fuel level.
- Torque type: Nm = (x-16000)/80, anchored at 0xC3FA8. It converts kW to Nm with 60000/2π, stores Nm*80+16000, and clamps
  at exactly the u16 range. The requested-torque pedal maps are identified, and FFFF0A62 is the Requested Torque X axis of the boost maps.
- FFFF299C = engine speed / 25 (0x143640, from the crank period). Target throttle T_02CA14 (FFFF0AF4, SSM 0x15).
- DTC table at 0x1B2D8: 291 codes, P/C/B/U in the top 2 bits. Reporter 0x5FBFE(index). The dispatchers call each monitor and then
  report its indices (subsystems.dtc_map). Few table-bearing tasks sit under these dispatchers, so the diagnostic tables
  (tasks 0xF6B24, 0xB42AC, 0x1011EC, 0x11F134 and others) still need monitor-flag tracing.
- Known blind spot: knock retard FFFF04AD and injector pulse width FFFF2B4E are written by code Ghidra did not discover
  (for example the region around 0x154C60 that writes FFFF2994/FFFF299C). Next: create functions in 0x150000-0x15A000 and re-export.

## Key proven chains
- **Ignition.** `0x98FAC`: total timing `FFFF046C` (SSM 0x11, deg = x/2) is the sum of components in 0.5° units. The base comes from four 22x16 maps (`0x86758`), selected by `FFFF04F4.7` and `FFFF054A.4`.
- **Engine load.** `FFFF09B4` / `FFFF03A0` = VE·ρ / 1.293 g/L × 100 %. This is the speed-density model `0xCFEDC`, with R = 287 and VE = `T_02ED10`/32768.
- **Boost.** Wastegate duty `FFFF0E5E` (SSM 0x30, % = x/256) = min(initial × compensation + PI feedback, max). The target boost encoding, kPa = x/256 + 13.3, is proven from A/D channel 0x12.
- **Open-loop fuel.** OBD PID 44 formatter `0x10C32C`: λ = 256/(256 + `0B84` + `0401` + `0B42`). The fuel tables use the expression λ = 256/(256+x).

## Session 3
- Coverage (latest): 1247 table views (1046 descriptor + 144 helper + 57 scalars); identified 236 tables + 57 scalars = 293 unlocked;
  810/1392 axes scaled; 1151/1561 lookup inputs resolved. Both ROMs PASS RomRaider validation (VerifyNamedDefinition, now with 1D support).
- New proof tools: `scalar_reads.py` scans for calibration scalar reads (3669 candidates); `scalar_semantics.py` proves a scalar
  when its folded value is compared with a proven variable; `table_compare.py` proves a table's output unit when it is compared with
  a proven variable. `stackargs.py` now also records value arguments (`V2:FFFFxxxx`, loaded from constant/GBR RAM), which
  `resolve_inputs`, `table_compare` and `scalar_semantics` use when the C prototype dropped an argument.
- Target idle speed: SSM 0x70/0x71 user adjustment -> 0xAB210 -> 0xAB09C target = 0D0A/4 + adj*128 - 0x4000 proves FFFF0D0A
  (rpm = x*25/512). The 0xAB238 helper tables 0x1348C..0x1354C (rpm = x*25/128, by mode FFFF04D7 vs coolant) and 22 ramp-rate tables
  (0xAB3C4) are identified.
- Target fuel rail pressure FFFF1276: OBD PID 0x6D bytes B-C (0x3169C PID pointer table -> handler 0x71C92), kPa = x*1250/2048,
  matching the actual FRP conversion. 9 maps in 0x1008D0 are identified (u8 maps x150).
- The builder makes names unique, because RomRaider silently merges tables with identical names.
- `scripts/stackargs.py` is an instruction-level call-site resolver that writes `evidence/stack-args.tsv`. It records constant r4..r7
  and pushed stack arguments, tracks stack slots and handles the delay slot. Ghidra drops many stack arguments, so this recovered
  output pointers that were missing: AVCS 0xF8EE0 -> 11B8..11BE, knock 0x9F368 -> 04AD, 0xA2F20 -> 04BA. Table sinks went from 403 to 461.
- `scripts/leads2.py`: 2-hop leads, from a table's sink variable to a reader function to a proven variable (init functions excluded).
- `subsystems.py`: labelled functions are now treated as roots, so the orphan dispatchers (0x15307C…) no longer hide their labels.
- AVCS targets (intake 0xF8EE0, exhaust 0xFC52C): T = Tbase*Tect/128 + TA*(1-w) + TB*w, deg = x*180/65536. The intake target
  goes through 0xF92CC (deg float, ±90 clamp) to 11C0/11C4 and is compared with cam angles EF2AC/EF2AE. The exhaust target is
  compared with SSM 0x118/0x119.
- Knock: FLKC unit deg = x*45/128 (SSM 0x199 converter 0xD0D50). 04A4 = IAM*04BA/16. 04BA = blend of the Knock Correction Advance Max
  maps T_02DA80/T_02DA94 (w = FFFF0E90). Knock retard 04AD uses constant steps (-4 per knock, +1 recovery, floor -0x22) in 0x9F368.
- Ignition term 047B (0x9A05C): 127.5 deg × product of five x/255 factors, chosen per gear (FFFEF51A) and by the oscillation counter FFFF0481.
- Catalyst temperature model (OBD PID 3C, 0xD9D40): steady-state and initial maps (C = 4x-40) and rate factors.
- Ignition final-sum inputs: IAT adder T_02D614, restore step tables, post-event limit T_02D5F0, retard hold count T_02D494.

## Session 3, continued
- Coverage: 1254 table views; 249 tables + 64 scalars unlocked (313). Both ROMs PASS.
- Target lambda maps (0xB5B38): AFR = (T + ...)*14.5/43194, stored as AFR*65536/22. 43194 = lambda 1.0, the same value as the A/F sensor #1 scaling.
  FFFF0D80 (SSM 0xD1) is NOT a proof here: 0xB53D4 overwrites it in the same task.
- Injector: FFFF1544 (base pulse) uses the same 0.8 us packing as FFFF1564, so T_02CE90 is a pulse multiplier x/256 (about 1/sqrt(FRP)).
  T_02D2C8 is a fuel-quantity multiplier x/128. Upstream, the fuel quantity is FFFF09BE x trims (09BE unit still unproven).
- Engine-speed limit: 0x85B74 limit = 6100 rpm scalars (0x87BA/BC/BE) only when FFFEF3FC/FFFEF498/FFFEF32E flags are set (otherwise none),
  with minimum margin 0x87B8 above FFFF0D06 and hysteresis 0x87B6. rpm >= limit -> FFFF03CF = 4 -> FFFF03D8.1. The injector fuel-cut
  bit FFFF03E4.7 comes from FFFF03D4 (0x86B80: FFFF0AF2 > 100/200), not from this limit. Torque mode 0x0B is entered at 6100 rpm and
  left at 6000 rpm (0x82C50, scalars 0xE666/0xE668).

- Task timing anchor: OBD PID 0x1F (run time, s) = FFFEF35E (0x10BE50 copy -> 12E0 -> 39C4, handler 0x718AA). 0x4EDAE
  increments it once every 25 executions, so 0x4EDAE's task 0x153248 (also called from 0x153D20) runs every 40 ms. Counters
  incremented once per execution in that task are therefore in 40 ms units. Second, independent anchor: 0x153248 runs 0x10C4DC
  once every 25 executions (prescaler FFFEF3AB = 0x19), and 0x10C4DC adds 1 to FFFF3B30, the seconds counter behind OBD PID 0x4E
  (minutes = s/60, 0x10BB94). Both give 25 x 40 ms = 1 s. Next: find counter-vs-table comparisons in the 0x153248 tree.
- Fixed: scanners now bound functions by the next function start. Ghidra sizes truncated large functions, e.g. 0x9CBF8 missed its
  0x98FAC call.
